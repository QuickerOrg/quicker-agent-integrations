# Quicker 外部 Agent 接入约定

本仓库维护外部 Agent 的连接、安装与使用引导。Quicker 提供动作工具、实时知识、草稿存储和审批。各平台适配遵循本文，平台交付要求见[新增平台](新增平台.md)。

当前 Codex 为原型，Cursor 尚在规划。现有连接面适用启用 MCP 的 Windows Quicker Debug 版；当前 Release 没有 MCP 入口或监听能力。安装插件不会开启 Quicker 的 MCP 或写入权限。

## 连接与发现

连接本机 Quicker 的 `http://127.0.0.1:<port>/mcp`，使用 Streamable HTTP。现有服务传输无状态，每个 POST 独立；编写状态由 Quicker 按客户端进程隔离。客户端若需要 stdio，由安装包内的转接脚本适配。

转接每次请求读取当前用户的 `~/.quicker/mcp/server.json`，取得 `Enabled`、`Port`、`Token`；`AllowWrites` 可用于只读诊断。文件缺失、配置无效、MCP 未启用或 token 缺失时，返回可识别错误。端口可变，主机固定为 `127.0.0.1`，拒绝 HTTP 代理与重定向。

完成 MCP 初始化后，使用协商结果和 `tools/list` 发现能力，不把固定工具清单当作当前可用清单。完整保留 `initialize.instructions`、工具 schema、全部 `content` 块、`structuredContent` 和 `attachedRules`。转接不得重写工具名、吞掉附加规则或损失 JSON 数字精度。stdio 的 stdout 只输出协议消息，诊断写入 stderr。

## 凭据与权限

请求使用 `Authorization: Bearer <token>`。token 只在本机读取并用于请求，不进入插件包、平台配置、命令行参数、日志或对话；错误信息不得回显请求正文或服务端错误页。

保留 Quicker 的客户端同意与工具审批流程。连接标识应准确区分平台，`Mcp-Client-Info` 只作识别信息，不能用来授予权限。首次连接给同意窗口留下有界等待时间，插件不得自动批准或编辑 `server.json`、`clients.json` 来启用服务、授权客户端或修改审批模式。

写工具缺失通常表示「允许 MCP 写入」未启用。通过 Quicker 设置处理，再按客户端机制重新发现工具。用户授权范围和 Quicker 运行时权限共同约束执行；平台技能不另造一套固定审批规则。

## 动作编写

运行时知识为准，插件只携带流程引导，不复制模块目录、DSL 或完整步骤知识。

1. 编辑前调用 `skill_load`，加载 `action-source`。陌生步骤先在 `@knowledge/catalog` 搜索关键词，再读取匹配 YAML；按需用 `quicker_eval` 的 `steps.resolve` 查询当前分支或引用文档。Host JS 使用 JavaScript，动作 `$=` 表达式使用 Quicker 的 C# 表达式语法。
2. 新建用 `quicker_create`；修改已有动作用 `quicker_search` 找到明确目标后 `quicker_open`。打开正式动作产生编辑草稿。
3. 保留返回的 slot 和 actionId。文件操作始终使用 `<slot>/program.source.yaml`、`<slot>/info.yaml` 或 `<slot>/files/...`；保存传 `quicker_save {"path":"<slot>"}`。这些是 Quicker 虚拟路径，必须使用 Quicker 的文件工具，不能交给本地文件系统工具。
4. `program.source.yaml` 写程序，`info.yaml` 写标题、说明和外观；`data.json`、`info.json` 为 Host 内部文件。保存后检查校验结果并修复错误。
5. 默认交付保存到暂存区的草稿。需要展示时调用 `quicker_preview {"target":"<slot>"}`；浏览器只打开工具实际返回的 URL。

不同客户端或任务仍可能编辑同一动作，必须串行处理同一 slot，不能依赖隐式当前位置。保存草稿、保留到场景、覆盖原动作和运行是不同结果：用户指定唯一既有目标场景时才 promote；overwrite、run 按用户请求和 Quicker 审批执行。完成说明应写清实际到达哪一步。

## 错误与恢复

同时检查 JSON-RPC error、MCP `isError`、`{ok:false,code,message}` 与 `quicker_eval` 的 `{error:...}`，不能把收到文本当作成功。

| 情况 | 处理 |
| --- | --- |
| HTTP 401 | 检查当前 Quicker 实例与认证状态；转接下一请求重新读取 token，避免输出配置文件。 |
| HTTP 403 | 引导用户在 Quicker 中同意准确的客户端，再连接；不得伪装其他已获授权客户端。 |
| 写调用超时、断连或 `stateUnknown` | 先检查相关 slot 或动作状态，再决定是否重试；转接不得自动重放写请求。 |
| 创建报告 `programCreated` 并带 actionId | 打开该动作恢复，不重复创建。 |
| `catalog_stale`、`catalog_freshness_unknown` | 核对当前动作并保留待保存修改，不盲目覆盖或重新打开脏草稿。 |

诊断应说明可操作的下一步，同时保留原始错误层级。协议测试通过只证明转接行为；真实客户端安装、Quicker 同意、草稿保存和预览需要单独验收。
