## 版本记录

每个平台使用自己的插件 manifest 版本。发布记录应包含平台版本、Quicker 版本或构建、操作系统、插件版本与实测结果。尚未实测的最低版本写为未知，不猜测兼容范围。

当前 Codex 包版本为 `0.1.1`，通过 GitHub 市场分发。旧个人市场原型使用的 `+codex.<时间戳>` 后缀只用于刷新开发缓存，不代表跨平台发布版本。

`0.1.1` 修复 `0.1.0` 安装成功但 MCP 无法启动的问题：当前 Codex legacy MCP 加载器不会展开参数中的 `${PLUGIN_ROOT}`，现改用 `cwd: "."` 与包内相对脚本路径。旧版用户按 README 的市场升级与重新安装步骤更新。隔离 HTTP fixture 用于传输回归，真实 Quicker 验收证据见下。

Release 支持与默认技能包发现修复已实现，待包含这些变更的正式版发布。受支持的新构建在设置 → Agent 中提供「启用 MCP」入口，Debug / Release 均默认关闭；用户要编写动作，还需开启「允许 MCP 写入」并完成客户端同意，loopback、Bearer 与工具审批边界不变。支持 MCP 的 Release 构建在 Quicker 内嵌设计器中预览，不返回 HTTP URL；只有 Debug + Vite 时才可能返回浏览器 URL。

上述产品变更尚未正式发布，已发布旧版没有 MCP 入口时仍不可用。插件 0.1.1 的安装成功不表示产品已具备 MCP 能力；Release 配置内核测试已通过，最低适用正式版本与正式安装包端到端结果仍待确认。

## 真实验收

2026-09-07 在 Windows 上，使用已从公开市场安装的 `quicker@quicker-agent-integrations` 0.1.1 完成以下验证：

- Codex app-server 在真实用户配置下识别已安装并启用的插件，未使用隔离的 Codex 配置目录。按安装缓存内 `.mcp.json` 启动 Windows PowerShell 5.1 转接，成功连接真实 Quicker。
- 初始化返回运行时技能索引，发现 18 个工具，`skill_load(action-source)` 成功。
- 创建测试草稿、写入程序，`quicker_save` 返回 `saved=true`；读回规范化 YAML 与动作信息，核对内容一致。
- `quicker_preview` 返回设计器 URL；实际浏览器中的设计器显示对应标题、提示消息步骤及本机暂存提示。

Quicker MCP 服务报告版本为 `2.3.0`，但本次使用包含默认技能包发现修复的本地 Debug 构建，该修复尚未公开发布。上述结果不代表所有 `2.3.0` 或其他 Debug 构建均兼容。动作没有执行，真实拒绝访问及只读切换也未验证。

后续构建复验时，使用用户授权的测试环境与一个容易识别的动作标题，记录具体构建范围，依次验证：

1. 从平台发现 Quicker 工具，读取运行时 action-source 技能。
2. 创建草稿，记录 actionId 和 slot，写入只显示提示的程序。
3. 保存成功后读回内容，并在 Quicker 暂存区核对动作。
4. 按用户要求打开设计器预览。需要验证运行时，先确认用户允许执行该动作。
5. 单独验证只读模式和客户端拒绝访问的行为，记录现象。
